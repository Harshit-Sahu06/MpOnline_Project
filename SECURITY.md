# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability.

Use the repository's private security reporting mechanism when available. If private reporting is not enabled, contact the repository maintainer privately through GitHub before sharing exploit details.

## Scope

Security reports are especially useful for:

- authentication or authorization bypasses;
- exposed secrets or credentials;
- unsafe file upload handling;
- injection vulnerabilities;
- unintended access to another user's data;
- security-sensitive dependency issues.

## Prototype notice

This is a hackathon prototype. Do not use real passwords, production API keys, sensitive resumes or other confidential personal data in development or demonstrations.

Never commit:

- API keys;
- JWT secrets;
- passwords;
- session tokens;
- private resume data;
- local database files.
